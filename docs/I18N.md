# Internationalisierung (i18n) — DE/EN

Foundation-Doku fuer Mehrsprachigkeit der Reporting Sub-App.

**Stand:** 2026-06-06
**Roadmap-Punkt:** #89 (FE, 1-2 Tage Vollausbau)
**Status:** Foundation-Doku heute. Vollausbau ist Folge-Sprint
sobald der Berater nicht-deutsche Kunden hat.

---

## Wann brauchen wir das?

- Kunde spricht kein Deutsch — Beratungsreport auf Englisch
- Berater betreut grenzueberschreitende Mandate (CH/DE/FR/IT)
- FINMA verlangt fuer auslaendische Kunden ggf. Englisch-Vorlage

Heute: Sub-App ist DE-only. Hauptapp ebenfalls DE.

## Strategie

**Library:** `react-i18next` (de-facto Standard, gratis, ADR-005-kompatibel)

**Sprach-Detection-Cascade:**
1. URL-Parameter `?lang=en` (Override fuer Demo)
2. localStorage `preferredLanguage`
3. `Mandate.advisory_language` aus Backend (DB-Feld, Pflicht: DE/EN/FR/IT)
4. `navigator.language` Browser-Default
5. `'de'` Fallback

**Translation-Files:** `src/i18n/locales/<lang>/<namespace>.json`

```
src/i18n/
├── index.ts                    (i18next-Setup)
├── locales/
│   ├── de/
│   │   ├── common.json         (Navigation, Errors, Buttons)
│   │   ├── advisory_report.json (Sektion-Titel, Disclaimer)
│   │   └── compliance.json     (FIDLEG-Texte)
│   └── en/
│       └── ... (Mirror)
```

## Foundation in U-89

Heute legen wir den Plan fest, **ohne** `react-i18next` zu
installieren (analog U-106/U-107: opt-in).

### Setup (opt-in)

```powershell
cd 5eyes-electron\frontend\reporting
npm install react-i18next i18next i18next-browser-languagedetector
```

### Beispiel-Setup `src/i18n/index.ts`

```ts
import i18n from 'i18next';
import { initReactI18next } from 'react-i18next';
import LanguageDetector from 'i18next-browser-languagedetector';

import deCommon from './locales/de/common.json';
import enCommon from './locales/en/common.json';

i18n
  .use(LanguageDetector)
  .use(initReactI18next)
  .init({
    resources: {
      de: { common: deCommon },
      en: { common: enCommon },
    },
    fallbackLng: 'de',
    interpolation: { escapeValue: false },
  });

export default i18n;
```

### Beispiel-Komponente

```tsx
import { useTranslation } from 'react-i18next';

export function Disclaimer() {
  const { t } = useTranslation('common');
  return <p>{t('disclaimer.intro')}</p>;
}
```

## Branding-Disziplin

- **KEINE Drittmarken in Translation-Files** (siehe
  [GLOSSAR.md](GLOSSAR.md#begriffe-die-nicht-auftauchen-duerfen))
- **KEINE Garantie-Sprache** in EN-Texten (auch nicht
  "guaranteed", "secured", "risk-free")
- **Editorial-Stil bleibt** in beiden Sprachen — Cormorant + Inter
  funktionieren auch fuer EN

## Backend-Integration

Bestehend: `Mandate.advisory_language` ist bereits DE-Default
(`5eyes-backend/models/mandates.py`). Mehr-Sprach-Output:

1. Aggregator-Sektion-Texte: heute hardcoded DE -> Folge-Sprint
   uebersetzbar mit `?lang=`-Query-Param
2. PDF-Renderer-Texte: gleicher Mechanismus, separater Sprint
3. Disclaimer + FIDLEG-Texte: brauchen Anwalts-Review pro Sprache

## Wechsel-Pattern fuer Berater

Sub-App-Sidebar bekommt einen Sprach-Selector (Folge-Sprint, analog
ThemeToggle U-50):

```tsx
<LanguageSelector />  // Dropdown DE/EN/FR/IT
```

Bei Wechsel:
- `i18n.changeLanguage(lang)`
- localStorage write
- Re-Render der gesamten Sub-App via React-Context
